## BSP 驱动移植到 AT32F403A + LCD 点亮 + DMA Demo

**结果**：`mdk_v5` 编译 0 Error / 0 Warning，Code=19822 RO=3262 RW=120 ZI=2752。

### 引脚分配（AT32F403A）
| 信号 | 引脚 | 说明 |
|---|---|---|
| TFT_LED (BL) | PA3 | 推挽输出，`st7789_init` 自动拉高 |
| TFT_CS | PA4 | 推挽输出，走 SPI 层 `spi_port_set_cs` |
| TFT_SCK | PA5 | GPIO_MODE_MUX（SPI1 默认映射） |
| TFT_A0/DC | PA6 | 普通推挽输出（**抢占 SPI1 的 MISO**） |
| TFT_SDA/MOSI | PA7 | GPIO_MODE_MUX |
| TFT_RESET | PB0 | 推挽输出 |

### 关键技术决策
1. **单线半双工发送** `SPI_TRANSMIT_HALF_DUPLEX_TX`：PA6 被 DC 占用，SPI1 不能占 MISO。
2. **DMA 固定请求映射**（与 STM32 不同）：SPI1_TX→DMA1_CH3，SPI2_TX→DMA1_CH5，SPI3_TX→DMA2_CH2。
3. **DMA 完成后再等 `SPI_I2S_BF_FLAG` 清零**，否则 CS 提前拉高会截断最后一字节（屏幕边缘花点）。
4. **`SPI_DMA_MIN_LEN 16`**：短包（命令/参数）走轮询，长包（整行像素）走 DMA。
5. **新增 `g_spi_hw_pins[]` 表**：无 CubeMX MspInit，SCK/MOSI 的 MUX 配置必须显式登记。
6. **SPI 速率**：`VERY_FAST` → APB2 120MHz / 8 = **15MHz**，全屏 240x320x2≈82ms ≈12fps。若花屏降为 `FAST`（7.5MHz）。

### 符号冲突（两套 SDK 不能共存于同一编译单元）
统一把通用 BSP 层的裸名重命名隔离，**框架文件不动**：
- `gpio_init(` → `gpio_pin_init(`
- `gpio_port_write` → `gpio_port_set_level`
- `spi_init(` → `spi_bus_init(`
- 通用层枚举 `GPIO_PULL_*` → `GPIO_PU_*`（AT32 SDK 自己保留 `GPIO_PULL_*`）

### 踩坑
- `gpio_port_at32.c` 的 `gpio_port_set_dir` 里 `cfg.pull` 是**通用层** `gpio_pull_t`，误赋 AT32 的 `GPIO_PULL_NONE` → `#188-D` 枚举混用警告。改 `GPIO_PU_NONE`。
- `st7789.c` 用 `sed 's/HAL_Delay(/delay_ms(/g'` 替换延时；结构体成员名 `delay_ms` 未被误伤（成员访问不带 `(`）。
- ARMCC v5 默认 C90，`uC99` 必须置 1（for 内声明、指定初始化器、stdbool.h）。

## 旋转编码器硬件正交解码（TMR4 / PB6+PB7）

**结果**：编译 0 Error / 0 Warning，Code=19382 RO=3326 RW=100 ZI=2740。

### 引脚依据
数据手册 DS V2.04 第29页（LQFP100 引脚42/43）：`PB6 = TMR4_CH1`、`PB7 = TMR4_CH2`，
是**默认复用通路**，不需要 IOMUX 重映射（`TMR4_MUX` 宏是重映射到 PD12~PD15 才用的，本工程不碰）。
PB6/PB7 与现有 LCD 引脚（PA3/PA4/PA5/PA6/PA7/PB0）不冲突；板载 LED 在 PD13/PD14/PD15。

### 配置要点
1. GPIO 用 `GPIO_MODE_INPUT + GPIO_PULL_UP`（**不需要 GPIO_MODE_MUX**，输入捕获只认输入模式）。
2. `tmr_base_init(TMR4, 0xFFFF, 0)` → 16 位满量程自由回绕；TMR4 **不支持** 32 位扩展（TMR2 才支持）。
3. `tmr_encoder_mode_config(TMR4, TMR_ENCODER_MODE_C, RISING, RISING)` = SMS=011，TI1/TI2 双边沿四倍频。
4. 库函数**不设输入滤波**，需直接写寄存器 `TMR4->cm1_input_bit.c1df/c2df = 0x0F`（fDTS/32 + N=8，吃机械抖动）。
5. 不用溢出中断：增量按 `(int16_t)(raw - last)` 算，16 位回绕天然安全，两次采样绝对变化 <32767 即可。
6. 换向不改接线：`encoder.h` 的 `ENC_DIR_INVERT` 置 1（等价反转 CH1 极性）。

### 验证界面
- 停用 `LcdDemo`（FILL/BOUNCE/TEXT 跑分），改 `EncoderDemo`：HUD 72px 显示 CNT/颜色/转向，下方 248px 纯色块。
- 每累计 4 个计数（一个 detent）换一色，8 色循环；静止时不刷屏，不占 SPI 带宽。
- 新任务 `TASK_ENCODER`（5ms 周期），`main.c` 中替换 `TASK_LCD`。

## KT06xx 芯片手册通读 + 与现有驱动交叉核对

**产物**：`Docs/KT/KT06xx_芯片知识卡.md`（寄存器级速查 + 时序链 + 易错点，18 节）

读完 `KT0656M_V0.7.8`（51 页）与 `KT0650_V0.1.2`（29 页），并与 `BSP/KT_Driver` 逐项对照。
结论：驱动整体与手册吻合，`kt0656m_cfg.h` 的地址/晶振/超时配置全部有手册依据。发现 4 处问题：

1. **0x0225 动的是保留位**：手册 V0.7.8 定义为 `AUTOMUTE_CFG0`（bit0 = `AUTOMUTE_MUTE_EN`，bit[7:1] 保留），
   驱动 `kt0656m.c:596` 当 `DC_NOTCH_MUTE_EN` 写 mask `0x0E` 清 bit[3:1]。bit0 未动所以静音总闸仍是默认开，
   但改保留位依赖未公开默认值 —— 属中低风险，改动前需实测。
2. **0x0256 bit[6:4] 命名错**：手册是 `EXP_TC`（扩展器时间常数，001=12ms），驱动叫 `KT_COMP_TC` 且注释
   写"温漂补偿档位"。取值无影响，但会误导。
3. **电池读数是 11bit 无符号**（0~2048，1.2V 参考），驱动当有符号取绝对值。因高字节仅 bit[2:0] 有效，
   `raw<0` 是死分支，结果正确，概念错。
4. **功能缺口**：`SQUEAL_CFG0` (0x026F) 啸叫抑制驱动完全未实现（手册 4.13.4 有手动/自动两模式，
   参数算法在 APP NOTE，datasheet 未公开）。

### 手册里最值得记住的坑
- `0x0012 bit7 XTAL_SEL` 与 `0x0108 bit7/6 XTAL1/2_SEL` 必须配对；单晶体必须接 XI-XO1，配错等于 PLL 永不锁且无报错。
- 16bit 寄存器（电池/BURST/AUX_DATA）**必须先读高字节**，芯片靠该动作锁存低字节。
- 中断标志 **写 0 清**（0x59），不是写 1 清。
- `ADJUST_GAIN` 编码不连续：0~4 = 75k/50k/37.5k/25k/20k，5/6 才跳回 120k/100k；手册 4.10 正文枚举顺序与寄存器表**不一致**，以表为准。
- EQ 的 0dB 是 `01100`；SAI 从模式 DSIZE `11` 是 8bit。
- 两颗芯片 `MANUFACTURER_ID` 都是 0x4B54，**不能靠 CHIP_ID 区分型号**，只能靠 I2C 地址的型号位。
- 手册自相矛盾：表 4 灵敏度 -108dBm@12dB SINAD，4.1 正文写 -93dBm@80dB，以表 4 为准。

### 认知修正
datasheet 只公开"客户需要配的那一层"。射频校准、VCO 频段表、LDO/BIAS/噪声等出厂参数层
（0x000D/0x0010/0x0016~0x001E/0x0064~0x0069/0x0109/0x0133 等约 20 个地址）手册完全没写，
只存在于原厂参考代码里。**改这些寄存器没有文档兜底，必须一次改一位 + 上板实测。**

## IIC_Driver + KT_Driver 移植到 AT32F403A（双组 KT）

**结果**：`mdk_v5` 编译 0 Error / 0 Warning，Code=19996 RO=2716 RW=124 ZI=2836

### 引脚（两组完全独立，各一条软件 IIC + 各一根 EN）
| | 组1 KT_CH_A | 组2 KT_CH_B |
|---|---|---|
| SCL | PB13 | PA9 |
| SDA | PB14 | PA10 |
| CHIP_EN | PB12 | PA8 |
| INT | PB11（未启用，只留宏） | PB15（未启用，只留宏） |
| 地址 | 主 0x39 / 从 0x3D | 主 0x39 / 从 0x3D |

四颗 ADDR 全接高；两组独立总线所以同地址不冲突。

### 移植前发现的硬冲突（关键）
1. **PA9 是 AT32 BSP 的 USART1_TX**（`at32f403a_407_board.h:88` `PRINT_UART_TX_PIN = GPIO_PINS_9`）。
   组2 的 SCL 正好是 PA9 → 必须删掉 `main.c` 的 `uart_print_init(115200)`，
   否则 PA9 被配成 UART 复用推挽，软件 IIC 时序被打断。日志同时全关
   （`logger_cfg.h` 各级别 + `LOG_USE_PRINTF` 置 0，宏展开 `((void)0)`）。
2. `iic_cfg.h` 原有 `IIC_BUS_OLED`(PA6/PA7) 与 LCD 抢脚（PA6=TFT_A0/DC、PA7=TFT_SDA），已删条目。

### 驱动逻辑修正：in_fw_check 必须按角色过滤
`in_fw_check()` 原来无差别读 0x010F 与 `KT_FW_VERSION_VAL(0x11)` 比对。但 **KT0650 手册 V0.1.2
没有 0x010F 这个寄存器**，从路读回未定义值 → 从路 init 必报 `KT_ERR_FW_MISMATCH`，
表现为"每组从机永远 FAIL + 每 5s 重试无效"。已加 `if (!KT_IS_MAIN(dev)) return KT_OK;`。
其余段的角色过滤核对过：in_power / in_frontend / in_bpsk / in_lo_div / in_loband 都已有
`KT_IS_MAIN` 保护，in_xtal / in_demod / in_automute 用分支处理。

### 实现要点
- **组级电源用 dev->ch 当组号**，没往 `kt0656m_dev_t` 加字段——每组一 EN，ch 与组一一对应，零结构体改动
- `grp_run()` 用 `power_cycle(ch)` 而非 `power_on(ch)`：power_on 幂等，重试时若首次上电就是坏的
  会直接返回 OK 永远修不好；cycle 每次都是干净时序，代价 120ms
- LCD 布局按 320px 屏高算过：标题 22 + 2×(描述+主3行+从2行+间隔 4) + 汇总 18 = 264px 内
  （最初每段状态单独占行会到 336px，超出屏幕）
- 从路不显示 FW：KT0650 无 0x010F
- 按键 EXINT0=PA0 / LCD=PA3~PA7+PB0 / 编码器=PB6+PB7，与 KT 新引脚无冲突
