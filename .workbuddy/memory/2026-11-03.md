## BM Arch 移植到 AT32F403A（完成，编译 0 Error / 0 Warning）

**结论**：BM Arch 与 MCU 无关，契约仅 `bm_hal.h` 的 4 个函数，AT32 可直接移植。

**关键工程判断 — 时基源不用 SysTick**
- AT32 BSP 的 `delay_us()/delay_ms()`（`at32f403a_407_board.c`）把 SysTick 当一次性倒计时用：
  改写 `LOAD/VAL`、轮询 `COUNTFLAG`、用完关 `ENABLE`。
- 若再把 SysTick 配成 1ms 周期中断（TICKINT），BSP 每次 delay 都会破坏时基 → 冲突。
- 最终方案：**TMR2 溢出中断做 1ms 时基**，与 BSP SysTick 轮询延时完全解耦。
  - `crm_clocks_freq_get()` 取运行时频率；`ahb_freq != apb1_freq` 时定时器频率 = APB1 × 2。
  - 当前时钟树 sclk=240MHz / apb1=120MHz → TMR2 clk = 240MHz → div=239（1MHz 计数）→ pr=999（1ms）。

**新增文件**
- `inc/bm_hal_port.h`：声明 `BM_HAL_TickInit()`（保持 bm_hal.h 契约纯净）
- `src/bm_hal.c`：4 个契约函数 + TMR2 时基；`BM_Delay()` 复用 BSP `delay_ms`；
  临界区用**嵌套计数**（否则 ISR 内 `MsgQueue_Send` 的 ExitCritical 会提前开中断，破坏外层临界区）
- `inc/app.h` + `src/app.c`：LED 流水灯任务、EXINT0 只投消息、按键软件消抖 200ms + `Scheduler_SetPeriod`

**框架扩展点改动**
- `scheduler.h`：`TaskHandle_t` 追加 `TASK_LED` / `TASK_EVENT`
- `msg_queue.h`：`MsgType_t` 追加 `MSG_BUTTON_PRESSED`
- `app_events.c`：switch 追加 `case MSG_BUTTON_PRESSED: App_OnButtonPressed();`
- `main.c`：重写为 BM Arch 启动序列（时钟 → 板级 → 串口 → TickInit → Logger → Scheduler → 任务注册 → while(1)）

**工程配置**
- `uvprojx`：`<uC99>0</uC99>` → `1`（框架用 for 内声明、指定初始化器、stdbool，ARMCC v5 C90 会报错）
- user 组加入 7 个新 .c

**资源**：Code 12574 B / RO 13700 B / RW+ZI 2168 B（AT32F403AVGT7 有 1MB Flash，无压力）

**待硬件验证**：LED 流水灯 100ms、按键升沿切 400ms、串口 115200 日志 `[tick][INFO][APP] button pressed -> FAST`
